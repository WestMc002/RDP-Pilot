RDP Pilot
=================
Legt in .rdp-Dateien fest, auf welchem Monitor bzw. welchen Monitoren
eine Remotedesktop-Sitzung startet.

Erstellen
Erstellen.bat per Doppelklick ausführen. Benötigt .NET Framework 4.x (csc.exe).
Versionsnummer: Haupt.Neben.Jahr.MonatTag (z.B. 1.4.2026.1029).
Die Hauptversion steht in Erstellen.bat (MAJOR), die Nebenversion wird bei
jedem Erstellen automatisch um eins erhöht (höchste vorhandene Version + 1).
Bei Fehlern bleibt die alte EXE unverändert; Details stehen in Erstellen.log.
Nach dem Erstellen werden Vorschaubilder im Ordner Design\Vorschau erzeugt.
Auf Nachfrage (J, ohne Antwort nach 10 Sekunden Nein) erstellt sie außerdem die
Screenshots für GitHub im Ordner Screenshots – nur aus Beispieldaten
(erfundene Verbindungen und drei feste Beispielmonitore), hell und dunkel.
Direkt: "RDP Pilot.exe" --screenshots [Zielordner]

Backup
Nach jedem erfolgreichen Erstellen wird das gesamte Projekt (EXE, Quellcode,
Resources, Design, Anleitungen usw.) in einen eigenen Versionsordner kopiert:
Backup\RDP Pilot v<Version>
Ordnernamen im Projekt werden groß geschrieben (Backup, Design, Quellcode, Resources).
Erstellen.bat folgt der Standard-Vorlage (Globale Richtlinien).

Bedienung
Die EXE liest alle .rdp-Dateien aus ihrem eigenen Ordner ein.
Verbindung oben auswählen, Monitore in der Karte anklicken (mehrere möglich),
dann "Speichern & verbinden" oder "Speichern".
Weitere Dateien über "Andere Datei …" oder per Drag & Drop aufs Fenster. Sie werden
gemerkt und stehen beim nächsten Start wieder in der Liste; die zuletzt gewählte
Verbindung ist dann gleich ausgewählt.
Neue oder gelöschte .rdp-Dateien im Ordner erscheinen von selbst in der Liste;
F5 liest Ordner und Bildschirme von Hand neu ein.
"Identifizieren" blendet auf jedem Bildschirm kurz groß seine Nummer ein.
Ändern sich die Bildschirme, während das Programm läuft (z.B. Notebook an- oder
abgedockt), liest es sie neu ein. Ist eine Verbindung auf Bildschirme eingestellt,
die gerade nicht angeschlossen sind, warnt die Infozeile.
"Nur verbinden" verbindet auf den Monitoren, die gerade ausgewählt sind, ohne die
Verbindung zu ändern (dafür wird eine Kopie im Temp-Ordner gestartet). Ist nichts
geändert, wird die Verbindung direkt gestartet; fehlen dann gespeicherte
Bildschirme, fragt das Programm vorher nach.
Option "Sicherung erstellen" (standardmäßig aus): beim Speichern wird das
Original als <Datei>.rdp.bak gesichert, sofern noch keine Sicherung existiert.
"Original wiederherstellen" spielt sie zurück.

Design: Windows-11-Standard (Fluent) – Farben, Ecken und Schrift wie Windows 11,
helles/dunkles Design und Akzentfarbe werden aus Windows übernommen.

Ein Monitor:      use multimon:i:0, winposstr auf den Monitor, Auflösung optional
Mehrere Monitore: use multimon:i:1, selectedmonitors (erste ID = Hauptmonitor)

Hauptmonitor
Der Hauptmonitor ist der Monitor, auf dem in der Remote-Sitzung Taskleiste und
Startmenü erscheinen. Rechtsklick auf einen Monitor (oder Taste H) legt ihn fest.
Ohne Festlegung: lokaler Primärmonitor, falls ausgewählt, sonst der linke.
"Primär" kennzeichnet den Hauptbildschirm deines lokalen Windows.

Kommandozeile
"RDP Pilot.exe" Test.rdp 2,1            Monitore setzen (erster = Hauptmonitor)
"RDP Pilot.exe" Test.rdp 2,1 /connect   setzen und verbinden
Zusätzlich /backup: vorher Sicherung .rdp.bak anlegen

Quellcode: Quellcode\*.cs   Grafiken: Resources (Icon, App-Icon, GS-Logo)
Entwürfe: Design (Vorschaubilder)

Info-Fenster
Klick auf die Versionsnummer oben öffnet das Info-Fenster mit Version,
Eckdaten, Anleitung und dem Ordner der Verbindungen.

Update-Prüfung
Kurz nach jedem Start wird still auf GitHub geprüft, ob es eine neuere Version
gibt (github.com/WestMc002/RDP-Pilot, nur lesend, ohne Anmeldung). Gibt es
eine, erscheint oben im Fenster ein Hinweis mit "Jetzt aktualisieren",
"Release-Seite" und "Später". "Jetzt aktualisieren" lädt das ZIP, beendet das
Programm, ersetzt EXE und Liesmich (mit Sicherung) und startet neu; die
Verbindungen bleiben unverändert.
Installiert wird nur eine Version, die der Herausgeber signiert hat: Neben dem
ZIP liegt im Release eine signierte Prüfsumme (RDP-Pilot-<Version>.manifest).
Fehlt sie oder passt sie nicht, zeigt das Info-Fenster "Nicht signiert." bzw.
"Signatur ungültig." und es bleibt bei der Release-Seite.
Übernommen werden nur "RDP Pilot.exe" und "Liesmich.txt", erst nach dem Beenden
des Programms und jeweils in einem Schritt. Läuft RDP Pilot selbst gerade mit
Administratorrechten, startet es sich für das Update mit normalen Rechten neu und
installiert dort. Gibt es auf dem System keine normalen Rechte (Benutzerkonten-
steuerung aus oder eingebautes Konto "Administrator", z. B. auf Windows Server),
wird mit Administratorrechten aktualisiert, aber nur über einen geschützten
Arbeitsordner unter ProgramData. Schlägt ein
Update fehl, läuft die bisherige Version weiter; Einzelheiten stehen im
Fehlerprotokoll (%LOCALAPPDATA%\RDP Pilot\Fehler.log). Wurde ein Update
unterbrochen (z. B. durch einen Absturz), stellt RDP Pilot beim nächsten
"Jetzt aktualisieren" nach Rückfrage die vorherige Version wieder her; hatte es
noch nichts verändert, räumt RDP Pilot still auf.
Im Info-Fenster zeigt die Zeile "Updates" den Stand und die letzte Prüfung,
"Jetzt prüfen" prüft von Hand, "Automatisch prüfen" schaltet die Prüfung ab.
Bei einem Fehler steht dort eine kurze Meldung, die genaue Ursache unter "Details".
Automatisch aktualisieren (Standard aus, nur zusammen mit "Automatisch prüfen"):
eine neue Version wird ohne Rückfrage installiert, sobald das Programm nicht
beschäftigt ist (keine ungespeicherte Monitorauswahl, kein Dialog offen; sonst
wird alle 5 Minuten erneut versucht). Danach startet das Programm von selbst neu.
Liegt das Programm unter "Programme", fragt Windows bei jedem Update nach
Administratorrechten.
Gespeichert wird das unter %LOCALAPPDATA%\RDP Pilot\Einstellungen.ini.
Ohne Internet bleibt alles wie gewohnt, es erscheint keine Fehlermeldung.

Versionen
1.61  Update: Läuft RDP Pilot mit Administratorrechten, startet es sich für das Update
      mit normalen Rechten neu („--aktualisieren“) und installiert dort, statt nur auf
      den normalen Start zu verweisen. Ohne normale Rechte (Benutzerkontensteuerung aus,
      eingebautes Konto „Administrator“) aktualisiert es mit Administratorrechten über
      den geschützten Arbeitsordner unter ProgramData; auch die Wiederherstellung ist
      dann für solche Arbeitsordner möglich.
1.60  Update: Muster-Prüfungen von Journal, Manifest und Ordnernamen haben ein
      Zeitlimit (250 ms); läuft es ab, gelten die Daten als nicht prüfbar und werden
      abgelehnt. Die Muster für das Journal sind so geschrieben, dass ihre Laufzeit linear
      bleibt.
1.59  Update: Bricht ein Update von Version 1.54 unter „Programme“ ab, setzt RDP Pilot
      es nicht mehr mit Administratorrechten zurück (die Sicherungen dieser Version haben
      keine Prüfsumme), sondern bietet die Download-Seite zur Neuinstallation an.
1.58  Update: Steuerdateien des Updates (Start, Bestätigung, Freigabe) werden einmal
      geöffnet und höchstens 256 Bytes gelesen; größere oder unlesbare gelten als
      ungültig. Das Update mit Administratorrechten legt sein Ergebnis je Versuch als
      Letztes und vollständig im Arbeitsordner ab; der Neustart-Helfer liest nur diese
      Datei. Der Helfer merkt sich die Startzeit des Updates, damit eine neu vergebene
      Prozess-ID nicht mit ihm verwechselt wird; lässt sie sich nicht lesen, zählt nur das
      Ergebnis dieses Versuchs, und kommt es nicht binnen 2 Minuten, wird „offen“
      gemeldet. Wird eine Version vor 1.56 wiederhergestellt, zeigt der Helfer das
      Ergebnis selbst an; die gemeinsame Update.log wird nicht mehr beschrieben. Der
      Versuchsordner wird nur gelöscht, wenn das Ende des Updates belegt ist.
      Verbindungsliste (gemerkte, im Programmordner, beim Neuladen und bei der automatischen
      Vorauswahl): Lässt sich der Laufwerkstyp nicht sicher bestimmen (auch bei
      Gerätepfaden) oder führt ein Teil des Pfads über eine Verknüpfung, Abzweigung oder
      einen Cloud-Platzhalter, wird die Datei wie im Netzwerk erst beim Auswählen gelesen.
      Liegt der Programmordner selbst im Netzwerk oder hinter einer Umleitung, wird er
      weder von selbst aufgelistet noch überwacht; F5 liest ihn ein.
1.57  Update: Das Wiederherstellungsjournal hat ein festes Format mit Versionskennung und
      nennt vor dem ersten Austausch alle geplanten Dateien. Aufräumen und Wiederherstellen
      prüfen es nach denselben strengen Regeln; im Zweifel bleibt alles erhalten.
      Nicht abgeschlossene Updates aus 1.54 und 1.55 werden an ihrem jeweiligen Format
      erkannt und wiederhergestellt. Journal, Status und Sicherungen werden vor jedem
      Austausch dauerhaft auf den Datenträger geschrieben (auch bei Stromausfall).
      Ein Ziel darf im Journal nur einmal vorkommen. Die Wiederherstellung läuft wie das
      Update über ein geprüftes Skript, nie aus einer Instanz mit Administratorrechten,
      und meldet nach einem Abbruch mittendrin immer „offen“ statt neu zu starten.
      Schreibprobe im Programmordner mit Zufallsnamen; Explorer und Remotedesktop werden
      direkt über ihren festen Pfad gestartet.
      Mehrere Installationen stören sich beim Update nicht mehr: Jeder Versuch hat sein
      eigenes Ergebnis. Unter „Programme“ startet erst der Neustart-Helfer und dann das
      Update mit Administratorrechten. Es ändert erst etwas, wenn RDP Pilot es für genau
      diesen Versuch freigegeben hat – erst nachdem der Neustart-Helfer den Empfang
      bestätigt hat; scheitert ein Schritt davor, wird nichts verändert.
      Die alte Instanz wird an Prozess-ID und Startzeit erkannt. Nach einer
      Wiederherstellung meldet auch eine ältere Version das Ergebnis.
      Verbinden: Die Rückfrage zeigt Änderungen an Ziel, Gateway und sicherheitsrelevanten
      Einstellungen zuerst und vollständig, Typänderungen immer; „Alle Änderungen“ klappt
      die ungekürzte Gesamtliste auf.
1.55  Update: Prüfen, Aufräumen und Wiederherstellen laufen unter derselben Sperre wie das
      Update selbst; die Wiederherstellung prüft das Journal vollständig, bevor sie etwas
      zurücksetzt, und jede Sicherung über ihre Prüfsumme. Mit Administratorrechten werden
      nur geschützte Arbeitsordner und Sicherungen verwendet. Fehlerprotokoll wird ab
      256 KB umbenannt statt eingelesen.
      Verbinden: Auch geänderte Typen und die Reihenfolge doppelter Einträge zählen als
      Änderung; doppelte sicherheitsrelevante Einträge (z. B. Weiterleitungen, Anmeldung,
      Startprogramm) werden wie doppelte Zieleinträge abgelehnt.
1.54  Gemerkte Verbindungen im Netzwerk werden beim Start nicht mehr gelesen (kein
      Zugriff auf den Server), sondern erst, wenn man sie auswählt.
      Verbinden startet eine geprüfte Kopie der Verbindung: Hat sich das Ziel seit dem
      Laden geändert, fragt RDP Pilot nach; doppelte Ziel- oder Gateway-Einträge
      werden abgelehnt.
      Auch über die Kommandozeile (/connect) wird nur eine geprüfte Kopie gestartet.
      Speichern und Wiederherstellen prüfen unmittelbar vor dem Ersetzen noch einmal, ob
      ein anderes Programm die Datei geändert hat; Laufwerke ohne sicheres Ersetzen werden
      nicht mehr beschrieben.
      Beim Verbinden zählt jede Einstellung außer der Monitorauswahl: Hat sie sich seit
      dem Anzeigen geändert, zeigt RDP Pilot die Änderungen und fragt nach.
      Updates nur noch signiert: Installiert wird nur ein Release mit gültiger Signatur
      des Herausgebers; nur ein Update zur Zeit, jeder Versuch in einem eigenen
      Arbeitsordner, mit Administratorrechten geschützt unter ProgramData; das Programm
      läuft danach immer mit normalen Rechten.
      Update noch sicherer: Download und Update-Skript mit Größengrenzen, Dateien werden
      in einem Schritt ersetzt, mit Wiederherstellungsjournal; ein unterbrochenes Update
      wird beim nächsten Mal nach Rückfrage zurückgesetzt. Kein Update, solange RDP Pilot
      mit Administratorrechten läuft. Fehler stehen im Fehlerprotokoll (Fehler.log).
      Hinweisleiste bei wenig Platz zweizeilig.
      Wiederherstellen ersetzt die Datei nur, wenn sie seit dem Anzeigen unverändert ist.
1.53  Sicherheit: Update nur mit passender Prüfsumme von GitHub, Hilfsskript nicht
      mehr als Datei im Temp-Ordner, mit Administratorrechten in einem geschützten
      Arbeitsordner unter ProgramData; Neustart danach immer mit normalen Rechten.
      Bei einem Fehler wird der vorherige Stand aller Dateien wiederhergestellt.
      RDP-Dateien werden sicher ersetzt; wurde eine Datei inzwischen von einem anderen
      Programm geändert, fragt RDP Pilot nach, statt sie zu überschreiben.
      "Nur verbinden": eigene Kopie je Start, alte Kopien werden gelöscht.
1.52  Hinweisleiste "Neue Version": Knöpfe ohne helle Ecken
1.51  Fußzeile: Abstand nach oben und unten gleich
1.49  Programm heißt jetzt "RDP Pilot"; Info-Fenster im Design der anderen
      Programme (GS-Logo), Fußzeile mit Copyright und Website.
      Einstellungen werden übernommen.
      Ältere Versionen aktualisieren nicht selbst auf 1.49: ZIP von GitHub laden,
      "RDP Pilot.exe" an die Stelle der alten EXE setzen.
1.44  Info-Fenster: "Details" steht wie in den anderen Programmen direkt hinter der
      Kurzmeldung
1.43  Update-Prüfung bei jedem Start; neu: "Automatisch aktualisieren" im Info-Fenster
      (installiert neue Versionen ohne Rückfrage, Standard aus)
      Info-Fenster: Update-Zeile übersichtlicher; bei einem Fehler kurze Meldung,
      die genaue Ursache über "Details"
      "Nur verbinden" nutzt die Monitore, die gerade ausgewählt sind (vorher die
      zuletzt gespeicherten)
      Verbindungen aus anderen Ordnern ("Andere Datei …") werden gemerkt, die zuletzt
      gewählte Verbindung ist beim Start wieder ausgewählt
1.39  Verbindungsliste klappt am unteren Bildschirmrand nach oben auf und bleibt
      auf dem Bildschirm des Fensters
1.38  Verbindungsliste: gleicher Abstand zum Rahmen oben und unten
1.36  Hinweise beim Überfahren mit der Maus kompakter und 15 Sekunden sichtbar
1.35  Neu: "Identifizieren" zeigt auf jedem Bildschirm seine Nummer
      Neu: geänderte Bildschirme und neue/gelöschte Verbindungen im Ordner werden
      von selbst erkannt ("Aktualisieren" entfällt, F5 liest von Hand neu ein)
      Neu: Warnung, wenn eine Verbindung auf Bildschirme eingestellt ist, die
      gerade nicht angeschlossen sind
1.34  Hinweise beim Überfahren mit der Maus (Tooltips) im Design des Programms
1.31  Meldungen und Rückfragen im Design des Programms (hell/dunkel) statt im
      Windows-Standardfenster
      "Original wiederherstellen" steht jetzt rechts, getrennt von den übrigen Knöpfen
1.28  Behoben: Bei mehreren Monitoren startete die Sitzung teils auf falschen oder

1.18  Prüfung auf Updates über GitHub mit Selbst-Update (Hinweis oben im Fenster,
